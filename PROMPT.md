## Роль и цель

Ты senior full-stack разработчик. Сделай простое, красивое и удобное веб-приложение для ведения **личного месячного бюджета** одним пользователем. Сейчас я веду бюджет в таблице (структура описана ниже). Структура удобная, а интерфейс нет. Нужен быстрый ввод операций (в том числе с телефона) и понятные ответы на вопросы:

1. Сколько денег пришло за месяц.
2. Куда они ушли, по категориям.
3. Сколько у меня **свободных денег**, то есть денег, не занятых регулярными обязательными платежами.
4. Сколько я **мог отложить** (по умолчанию максимум 10% от зарплаты) и сколько **отложил по факту**.
5. Сколько я ещё должен по кредиткам и личным долгам и как быстро гашу их.

Без лишних сложностей: один пользователь, без мультивалютности, без банковских интеграций.

## Стек

- **Next.js 15 (App Router) + TypeScript**, фронт и бэкенд в одном проекте (API через Route Handlers в `app/api/*`).
- **UI: TailAdmin (бесплатная версия для Next.js, Tailwind CSS)** как основа: сайдбар, хедер, карточки, таблицы, формы, тёмная тема. Графики на **ApexCharts** (уже есть в TailAdmin).
- **БД: SQLite через Prisma** (файл `prisma/dev.db`), миграции и сидинг через Prisma.
- Валидация через **zod** и на клиенте, и на сервере.
- Деньги хранить **в центах (Int)**, никаких float.
- Авторизация: один пароль из `.env` (`APP_PASSWORD`), cookie-сессия, middleware закрывает все страницы и API. Если переменная не задана, авторизация выключена.
- Запуск одной командой: `npm install && npx prisma migrate dev && npm run dev`. Добавь `Dockerfile` и `docker-compose.yml` с volume для файла БД.

## Язык и формат

- Интерфейс на **русском**.
- Валюта задаётся в настройках, по умолчанию **EUR (€)**. Формат `1 310,00 €`.
- Даты в формате `ДД.ММ.ГГГГ`, неделя начинается с понедельника.

## Модель данных (Prisma)

```
Settings (одна запись)
  currency            String   @default("EUR")
  savingsPercent      Int      @default(10)     // % от зарплаты, который «можно отложить»
  carryOverBalance    Boolean  @default(true)   // переносить остаток месяца в следующий

Category
  id, name, kind: EXPENSE | INCOME
  color, icon (название иконки)
  isMandatory  Boolean   // обязательные регулярные траты (жильё, коммуналка, связь, проезд, долги)
  isSalary     Boolean   // только для INCOME: считается «зарплатой» для расчёта % накоплений
  sortOrder, archived

Transaction
  id, date, amountCents (>0), description
  type: EXPENSE | INCOME | SAVING        // SAVING = перевод в накопления
  categoryId?                            // обязателен для EXPENSE и INCOME
  debtId?                                // если это платёж по долгу
  recurringId?                           // если это оплата регулярного платежа
  createdAt

MonthPlan                                // план по категории на месяц (колонка Planned в таблице)
  month ("2026-06"), categoryId, plannedCents
  @@unique([month, categoryId])

RecurringPayment                         // регулярные обязательные платежи-шаблоны
  id, name ("O2", "Strom", "DB"), amountCents, categoryId
  dayOfMonth?, debtId?, active

Debt                                     // кредитки и личные долги
  id, name ("TF Bank card", "Мама")
  type: CREDIT_CARD | PERSONAL | LOAN
  initialCents, minPaymentCents, interestRate?, note, closedAt?
```

Текущий остаток долга = `initialCents − сумма Transaction(debtId)`. Хранить его отдельным полем не нужно.

## Формулы (считать на бэкенде, один эндпоинт `GET /api/summary?month=YYYY-MM`)

Для выбранного месяца:

- **Начальный баланс** = конечный баланс прошлого месяца (если `carryOverBalance`), иначе 0.
- **Доход** = Σ INCOME.
- **Зарплата** = Σ INCOME в категориях с `isSalary`.
- **Расходы** = Σ EXPENSE.
- **Обязательные платежи** = Σ EXPENSE в категориях `isMandatory` **плюс** ещё не оплаченные в этом месяце активные `RecurringPayment` (по их плановой сумме). Так «свободные деньги» видны уже в начале месяца, до того как всё оплачено.
- **Свободные деньги** = Доход − Обязательные платежи.
- **Можно отложить** = min(Зарплата × `savingsPercent` / 100, max(Свободные деньги, 0)).
- **Отложено по факту** = Σ SAVING.
- **Ещё можно потратить** = Свободные деньги − необязательные расходы − Отложено по факту.
- **Конечный баланс** = Начальный баланс + Доход − Расходы − Отложено.
- По каждой категории: план, факт, разница, % выполнения плана.
- По долгам: остаток на начало и конец месяца, сколько погашено за месяц.

Расходы без категории запрещены формой. Если они всё же есть (например, после импорта), показать их отдельной строкой «Без категории» с предупреждением.

## Страницы

### 1. Дашборд `/` (главная)
- Сверху переключатель месяца (← Июнь 2026 →) и большая кнопка **«+ Операция»**.
- Ряд KPI-карточек: **Доход**, **Расходы**, **Свободные деньги**, **Ещё можно потратить**, **Конечный баланс**.
- Карточка **«Накопления»**: прогресс-бар «Отложено 0 € из 131 € возможных» и подпись «10% от зарплаты».
- Карточка **«Долги»**: общий остаток, сколько погашено в этом месяце, мини-список долгов с прогрессом.
- Донат-график расходов по категориям (клик по сектору открывает операции этой категории).
- Горизонтальные бары «план vs факт» по категориям расходов, перерасход красным.
- Таблица категорий: Категория | План | Факт | Разница (как в моей таблице, только красиво). Обязательные категории помечены бейджем.
- Блок **«Регулярные платежи этого месяца»**: список с чекбоксами «оплачено». Клик по чекбоксу создаёт EXPENSE-транзакцию с нужной категорией, суммой и долгом, сумму можно поправить перед сохранением.

### 2. Операции `/transactions`
- Табы: Все / Расходы / Доходы / Накопления. Фильтр по месяцу, категории и поиск по описанию.
- Таблица: Дата | Сумма | Описание | Категория (цветной бейдж) | Долг. Редактирование и удаление прямо в строке, удаление с подтверждением.
- Итоги по отфильтрованным операциям внизу.

### 3. Быстрое добавление операции (модалка или drawer, доступна отовсюду)
- Переключатель типа: Расход / Доход / Отложить.
- Первым полем **сумма** с автофокусом и цифровой клавиатурой на мобильных.
- Категория выбирается **плитками-чипами** с иконками, а не выпадающим списком.
- Дата по умолчанию сегодня, описание необязательное.
- Если категория «Долги», появляется выбор конкретного долга.
- Enter сохраняет. Есть кнопка «Сохранить и добавить ещё».

### 4. План месяца `/plan`
- Таблица категорий с редактируемой колонкой «План».
- Кнопка «Скопировать план из прошлого месяца».
- Плановый доход, обязательные платежи, свободные деньги и «можно отложить» пересчитываются вживую.

### 5. Долги `/debts`
- Карточки долгов: название, тип, начальная сумма, остаток, мин. платёж, прогресс-бар погашения, история платежей.
- Добавление, редактирование и закрытие долга.
- Общий итог: «Всего долгов: X €, погашено за месяц: Y €».
- (Простая оценка) «При текущем темпе погасишь примерно к <месяц год>».

### 6. Регулярные платежи `/recurring`
- CRUD шаблонов: название, сумма, категория, день месяца, связанный долг, активен ли.

### 7. Настройки `/settings`
- Категории: добавить, переименовать, выбрать цвет и иконку, флаги «обязательная» и «зарплата», порядок перетаскиванием, архивация.
- Процент накоплений, валюта, перенос остатка между месяцами.
- Экспорт всех операций в CSV и импорт из CSV (колонки Date, Amount, Description, Category, Type).

## Дизайн

- Основа TailAdmin: светлая и тёмная тема, сайдбар с иконками, на мобильных сайдбар сворачивается, а снизу появляется таб-бар (Дашборд, Операции, +, Долги, Ещё).
- Сдержанная палитра. Акцентный цвет для расходов тёплый оранжевый (как в моей таблице, `#E8703A`), для доходов и «отложено» зелёный или тёмно-синий, перерасход красный.
- Крупные цифры в KPI, моноширинные (tabular-nums) суммы в таблицах.
- Пустые состояния с подсказкой («Добавь первый доход за месяц»), скелетоны при загрузке, тосты после сохранения.
- Всё должно удобно работать на экране 375px.

## API (REST, JSON)

```
GET    /api/summary?month=YYYY-MM
GET    /api/transactions?month=&type=&categoryId=&q=
POST   /api/transactions          PATCH/DELETE /api/transactions/:id
GET    /api/categories            POST / PATCH / DELETE (архивация)
GET    /api/plan?month=           PUT /api/plan?month=   POST /api/plan/copy?from=&to=
GET    /api/recurring             POST / PATCH / DELETE
POST   /api/recurring/:id/pay?month=   // создаёт транзакцию
GET    /api/debts                 POST / PATCH / DELETE
GET    /api/settings              PUT /api/settings
GET    /api/export.csv            POST /api/import
```
